# Deployment Guide — bryanrea.com

## What's Running Where

Everything lives on a single **Digital Ocean VPS** (Ubuntu 24.04) at `bryanrea.com`.

```
/var/www/bryanrea.com/        ← the monorepo, cloned from GitHub
├── index.html                ← portfolio static site (served directly by Nginx)
├── about/, experience/, ...  ← other portfolio pages
├── shared/                   ← shared CSS, JS, images (also served by Nginx)
└── fragments/                ← Flask blog app (served via Gunicorn)
```

Three pieces of software work together to serve the site:

1. **Nginx** — the front door. Handles all incoming requests, terminates SSL, serves static files directly, and forwards `/fragments` requests to Gunicorn.
2. **Gunicorn** — runs the Flask Python app. Nginx hands off blog requests to it. It binds to `127.0.0.1:8000` (local only, not public).
3. **systemd** — keeps Gunicorn running. If the process crashes, systemd restarts it automatically. Also starts it on server reboot.

### Request flow

```
Browser → Nginx (SSL, port 443)
              ├── /              → serves /var/www/bryanrea.com/index.html directly
              ├── /shared/       → serves /var/www/bryanrea.com/shared/ directly
              ├── /fragments/    → forwards to Gunicorn → Flask app
              └── /sitemap.xml   → forwards to Gunicorn → Flask app
```

## Nginx Config

Located at `/etc/nginx/sites-available/bryanrea.com`.

```nginx
server {
    server_name bryanrea.com www.bryanrea.com;

    root /var/www/bryanrea.com;
    index index.html;

    # Portfolio static site + shared assets (CSS, JS, images)
    location / {
        try_files $uri $uri/ =404;
    }

    # Flask blog
    location /fragments {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # Sitemap (generated by Flask)
    location = /sitemap.xml {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # SSL managed by Certbot — don't edit these lines manually
    listen [::]:443 ssl ipv6only=on;
    listen 443 ssl;
    ssl_certificate /etc/letsencrypt/live/bryanrea.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/bryanrea.com/privkey.pem;
    include /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;
}

server {
    # Redirect HTTP → HTTPS (managed by Certbot)
    listen 80;
    listen [::]:80;
    server_name bryanrea.com www.bryanrea.com;
    return 301 https://$host$request_uri;
}
```

Useful Nginx commands:
```bash
nginx -t                        # Validate config before applying
systemctl reload nginx          # Apply config changes without downtime
systemctl restart nginx         # Full restart (causes brief downtime)
tail -f /var/log/nginx/error.log  # Watch for errors
```

### Gzip compression

`gzip on` lives in the stock `/etc/nginx/nginx.conf` but only compresses
`text/html` by default. The extra directives live in
`/etc/nginx/conf.d/gzip.conf` (added July 2026), which Nginx includes
automatically:

```nginx
# Gzip for text assets beyond the text/html default.
# gzip itself is enabled in nginx.conf; text/html is always included.
gzip_vary on;
gzip_proxied any;
gzip_comp_level 5;
gzip_min_length 256;
gzip_types
    text/plain
    text/css
    text/xml
    application/javascript
    application/json
    application/xml
    application/rss+xml
    image/svg+xml;
```

This covers both the static portfolio assets and the proxied Flask
responses (the RSS feed dropped from ~21.5 KB to ~8.8 KB, shared CSS from
~12.8 KB to ~4.3 KB). Verify from anywhere with:

```bash
curl -sI -H 'Accept-Encoding: gzip' https://bryanrea.com/shared/css/shared.css | grep -i content-encoding
```

## systemd Service

Located at `/etc/systemd/system/fragments-blog.service`.

```ini
[Unit]
Description=Fragments Blog (Gunicorn)
After=network.target

[Service]
User=www-data
Group=www-data
WorkingDirectory=/var/www/bryanrea.com/fragments
ExecStart=/var/www/bryanrea.com/fragments/venv/bin/gunicorn --workers 3 --bind 127.0.0.1:8000 app:app
Restart=always

[Install]
WantedBy=multi-user.target
```

**What each part means:**
- `User=www-data` — runs as the web server user, not root, for security
- `WorkingDirectory` — Gunicorn starts from here so it can find `app.py` and `posts/`
- `ExecStart` — uses the venv's Gunicorn, not a system-wide one; `--workers 3` handles concurrent requests
- `Restart=always` — auto-restarts if the process crashes
- `WantedBy=multi-user.target` — starts automatically on boot

Useful service commands:
```bash
systemctl start fragments-blog      # Start
systemctl stop fragments-blog       # Stop
systemctl restart fragments-blog    # Restart (after code changes)
systemctl status fragments-blog     # Check if running and see recent logs
systemctl enable fragments-blog     # Auto-start on reboot
journalctl -u fragments-blog -f     # Stream logs live
journalctl -u fragments-blog -n 50  # Last 50 log lines
```

## Standard Deploy Workflow

**Pushing to `main` auto-deploys the site.** A GitHub Actions workflow SSHes into the server, pulls the latest code, restarts the Flask service, and verifies it's running — usually within ~30 seconds of the push completing.

```bash
# Local
git add .
git commit -m "..."
git push origin main
# That's it. Watch the Actions tab on GitHub to see the deploy run.
```

The workflow lives at `.github/workflows/deploy.yml` and is also runnable manually from the **Actions** tab via the "Run workflow" button. Useful for re-deploying after a server-side change.

### What the workflow does

```yaml
script: |
  set -e
  cd /var/www/bryanrea.com
  git pull origin main
  fragments/venv/bin/pip install --upgrade -r fragments/requirements.txt
  systemctl restart fragments-blog
  systemctl is-active fragments-blog
```

`set -e` halts on any failure. The `pip install` line syncs Python deps into the service's virtualenv on every deploy — it's a fast no-op when `requirements.txt` is unchanged, and it means dependency bumps ship automatically with a normal push. `is-active` makes the Action fail loudly if Gunicorn crashes during restart instead of silently going green.

### Required GitHub repo secrets

| Name | Value |
|------|-------|
| `SSH_HOST` | `bryanrea.com` |
| `SSH_USER` | `root` |
| `SSH_KEY` | full contents of the deploy private key (`-----BEGIN OPENSSH PRIVATE KEY-----` to `-----END OPENSSH PRIVATE KEY-----`) |

The matching public key lives in `/root/.ssh/authorized_keys` on the server.

### When `requirements.txt` changes

The workflow installs dependencies into the venv on every deploy (`fragments/venv/bin/pip install --upgrade -r fragments/requirements.txt`), so adding or bumping a Python dependency ships automatically with a normal push to `main` — no manual SSH step needed.

If you ever need to install deps by hand (e.g. Actions is down):

```bash
ssh root@bryanrea.com
cd /var/www/bryanrea.com/fragments
source venv/bin/activate
pip install -r requirements.txt
deactivate
systemctl restart fragments-blog
```

### Manual deploy (if Actions is down or you're debugging)

```bash
ssh root@bryanrea.com
cd /var/www/bryanrea.com
git pull origin main
systemctl restart fragments-blog
systemctl status fragments-blog
```

Portfolio and shared asset changes (CSS, JS, HTML) take effect immediately on `git pull` — no restart needed. Only Flask app changes require a service restart.

## Initial Server Setup (for reference)

If ever rebuilding from scratch:

```bash
# Clone the repo
git clone git@github.com:bryanrea/bryanrea.com.git /var/www/bryanrea.com

# Set up Python venv
cd /var/www/bryanrea.com/fragments
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
deactivate

# Fix ownership so Nginx/Gunicorn can read the files
chown -R www-data:www-data /var/www/bryanrea.com

# Suppress Git's "dubious ownership" warning (files owned by www-data, git runs as root)
git config --global --add safe.directory /var/www/bryanrea.com

# Install and configure the systemd service
# (paste the service file content from above)
nano /etc/systemd/system/fragments-blog.service
systemctl daemon-reload
systemctl enable fragments-blog
systemctl start fragments-blog
```

## Troubleshooting

**502 Bad Gateway**
Gunicorn isn't running or isn't reachable. Check:
```bash
systemctl status fragments-blog     # Is it running?
ss -tlnp | grep 8000                # Is something listening on port 8000?
journalctl -u fragments-blog -n 30  # Any startup errors?
```

**Old version showing after deploy**
Another service may still be running old code. Check for stale processes:
```bash
ss -tlnp | grep 8000                         # See what's on port 8000
systemctl list-units --type=service | grep frag  # Look for old services
```
If an old service is found: `systemctl stop <old-service> && systemctl disable <old-service>`

**Git "dubious ownership" error**
```bash
git config --global --add safe.directory /var/www/bryanrea.com
```

**SSL certificate renewal**
Managed automatically by Certbot. Manual renewal if needed:
```bash
certbot renew
systemctl reload nginx
```
